# ADR1 - Program architecture

## Context
Pyslurm is a workload manager and job scheduler similar in behavior to Slurm. This project has been created for learning purposes to understand how resource scheduling works in heterogeneous computing
environments (Or a computing cluster).

## Options
1. A cli only implementation without a REST API
2. A REST API only implementation without a CLI

## Decision
In the first stage we will write a cli program that accepts some basic slurm commands in the form of a bash script. In the second stage, we will put a REST API layer on top of the CLI to facilitate access through a web-ui. 
We will implement a subset of the Slurm commands. Implementing full compatibility with the Slurm program is out of the scope of this project.

### V1 Scope
#### Commands
1. `sbatch script.sh`
This command will parse the bash script and perform the operations defined in the script. Command line flags override the script
2. `squeue [-u user] [-j job_id] [-t state]`
Default columns: JOBID, NAME, USER, ST, TIME, NODES, NODELIST(REASON)
4. `scancel <job-id>/scancel -u user`
Full detail of the job including the reason a job is pending
5. `sacct [-j job_id]`
Finished jobs: exit code, elapsed time, final state
6. `sinfo`
Node states (idle/mix/alloc/down) and resources
7. `scontrol update node=X state=drain/resume`
Required for fault injection simulations

#### SBATCH directives
- --job-name
- --ntasks
- --cpus-per-task
- --mem
- --gres=gpu:N
- --time
- --output,
- --error

#### Job states
- PENDING, RUNNING, COMPLETING, COMPLETED
- FAILED, CANCELLED, TIMEOUT

#### Deferred
- srun/salloc: interactive run blocks until task completes
- Partitions and QOS
- Job Arrays
- Dependencies
- scontrol hold/release
